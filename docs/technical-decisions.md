# Workflow Editor technical decisions

Technical implementation decisions complement the owner-approved product intent in [Decision Atlas](DECISION-ATLAS.md). They do not authorize new product behavior.

## TECH-001 — Registry-authoritative resolution of linked Node Templates

- **Status:** approved 2026-10-16, owner choice A; technical steering question TECH-001.
- **Context:** [Issue #65](https://github.com/moritzbrantner/workflow-editor/issues/65) implements linked, versioned Node Template instances across Workflow Documents. Product Decisions 2.9 and 2.11 require compatible edits to propagate, incompatible published revisions to remain available, explicit upgrade, and detach.
- **Decision:** The existing host-managed Editor Catalog / Node Template registry is the single authority for shared definition identities and immutable published revisions. A linked Node stores a stable template identity and its revision-resolution reference, not an independently authoritative embedded copy. Editor preview, graph validation, compiler and document restore resolve the effective published definition through the same registry contract. A compatible newer revision can become effective for linked instances, while incompatible changes retain the last compatible immutable revision until explicit upgrade. Missing definitions or revisions produce explicit, actionable diagnostics; do not silently materialize stale copies or rebind by display name.
- **Persistence and portability:** Save/export the reference and sufficient revision identity to reproduce the linked semantics. Import/restore must verify required definitions/revisions against the available registry and report missing dependencies. Full self-contained offline snapshots are *not* the default linked-node authority. Explicit **Detach / Unlink** materializes the currently resolved definition as an independent local Composed Node; it ceases following registry updates.
- **Ownership:** Workflow Editor owns linked authoring, registry integration, type validation and compilation; graph-editor owns generic graph interactions, and an external runner owns execution. Reuse the existing registry (#16), compiler (#19), and composition surfaces (#43). Do not add a second registry, document-level synchronization engine, or alternate TypeScript type checker.
- **Evidence required by #65:** two Workflow Documents referencing one published template, a compatible update propagating, an incompatible revision retaining old consumers, explicit upgrade, detach, save/reopen and import/export including missing-template behavior. No implementation or acceptance is claimed by recording this decision.
